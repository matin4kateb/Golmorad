# Trading decision experiment log

## Cycle 1: enforce backtest risk counters

- **Hypothesis:** Carrying daily entry count, daily loss, and marked-equity drawdown into every risk-gate check will make the walk-forward simulator reject entries once configured daily limits are reached. The change may reduce simulated activity when a strategy emits repeated same-day signals.
- **Baseline:** Existing `WalkForwardBacktest` passed `trades_today=0` and `daily_loss=0` for every entry and estimated drawdown from initial capital minus cash, so same-day trade and daily-loss limits could not be enforced correctly.
- **Data and split:** Stored `BTC-USD` daily candles, latest 2,000 rows returned by the database, 5 expanding chronological folds, first 51 rows reserved for indicator history, decisions made before the next execution candle. Observed range: 2021-04-20 through 2026-10-10 UTC; first test execution: 2021-06-10.
- **Configuration and costs:** Initial capital 10,000 quote units; fee 0.10% per fill; adverse half-spread 0.05%; adverse slippage 0.10%; maximum candle volume participation 5%; fixed `RiskGate` limits.
- **Baseline result before the code change:** 56 entries including one open position; 55 closed trades; net marked P&L 162.78; return 1.63%; max marked-equity drawdown 2.27%; mean realized P&L per closed trade 2.67. Closed-trade counts / P&L by entry fold: 8 / 33.01, 11 / 4.19, 10 / 80.74, 16 / 92.38, 11 / -47.54 (the final fold includes one open position; P&L totals include its marked unrealized P&L).
- **Change:** Maintain the UTC day entry count, daily starting equity, and peak marked equity; pass daily loss and peak-to-current drawdown amounts to `RiskGate`.
- **Result after the change on the same candles and settings:** 56 entries, 55 closed; net marked P&L 162.78; return 1.63%; max drawdown 2.27%. These values are unchanged because this saved-data run did not reach a daily limit. A deterministic same-day repeated-signal test confirms five entries are accepted and the sixth is rejected.
- **Uncertainty and limits:** No bootstrap interval is reported. These trades are serially dependent, and the repository's current evaluator does not calculate confidence intervals, calibration, regime attribution, or a dedicated untouched final holdout. The observed return is historical and does not establish future performance or a strategy improvement.
- **Decision:** Keep the correction as a risk-accounting fix, not as a performance claim. Do not promote or tune the strategy based on this run. Broader out-of-sample acceptance remains unproven.
- **Validation:** `python -m unittest discover -s tests -v` — 11 tests passed. No exchange calls were used.

## Cycle 2: prevent same-candle re-entry after a bracket exit

- **Hypothesis:** A candle that exits an existing position must not also create a new entry at that candle's open, because the exit is only known from the later high/low. Skipping re-entry on that candle removes an invalid ordering assumption and may lower trade count or return.
- **Baseline:** The prior loop resolved stop/target using the full candle range, then could evaluate a new signal and fill at that candle's open.
- **Change:** Track whether the existing position exited on the current candle and skip new entry evaluation for that candle.
- **Evaluation:** Same saved candles, 10,000 initial cash, same 5-fold split and the costs above. Before this change: 56 trades (55 closed), net marked P&L 162.78, return 1.63%, max drawdown 2.27%. After this change: 48 trades (47 closed, one open), net marked P&L 180.03, return 1.80%, max drawdown 1.89%, 19 winning closed trades, mean closed-trade P&L 3.50. A simple no-trade baseline returns 0 with zero drawdown. A capped 250-unit buy-and-hold baseline over the same test span, with the same fee and adverse spread/slippage assumptions, returns approximately 301.38 (3.01% of the 10,000 account); this uses continuous market exposure and is not directly risk-matched to the strategy.
- **Fold detail:** The five test folds contain 390, 390, 390, 390, and 389 bars. The current report groups trades by entry fold but does not calculate a comparable marked-equity result per fold.
- **Uncertainty and limits:** Results above are a single historical run. No bootstrap confidence interval, regime analysis, or untouched final holdout is available, so the apparent change in historical return is not evidence of a reliable strategy improvement. The capped buy-and-hold baseline also has a different exposure profile.
- **Decision:** Keep this timing correction because it removes an invalid same-candle execution sequence. Do not treat the return change as a strategy improvement or promote the ruleset based on it.
- **Validation:** `python -m unittest discover -s tests -v` — 12 tests passed, including same-day risk-limit and exit-candle re-entry regressions. `git diff --check` passed (Git emitted only pre-existing LF/CRLF notices). No exchange calls were used.

## Cycle 3: bounded chronological parameter selection

- **Execution prompt:** “Inspect the existing Golmorad repository and preserve unrelated work. Add a bounded, explainable spot-strategy parameter selector using only candles available before each decision. Select candidates on chronological validation data, report a separate untouched holdout, keep fees and the independent RiskGate fixed, prohibit leverage, fail closed when data is insufficient, integrate selection only into explicitly requested paper trading, and add clear CLI/documentation without enabling live exchange orders.”
- **Hypothesis:** Selecting a small, bounded set of spot strategy parameters on a chronological validation segment, then reporting a later untouched holdout, provides a reviewable parameter candidate without changing hard risk limits or using future candles in a paper decision.
- **Change:** Added a 9-combination search over ATR stop width, RSI upper threshold, and reward/risk ratio. The validation score is return percentage minus half the maximum drawdown percentage, with at least three closed trades required. If no candidate qualifies, the baseline settings are retained and the fallback is explicit. The first 60% of candles warms indicators; the next 20% selects settings; the final 20% is reported as an untouched holdout.
- **Paper integration:** `--auto-optimize` selects from candles strictly before the current decision candle. Missing/invalid/short history fails closed without creating a simulated order. Fixed RiskGate caps remain independent; leverage stays at 1.
- **Synthetic smoke check:** 300 deterministic synthetic daily candles produced 9 validation rows, a selected parameter record, and a completed separate holdout. This confirms code-path operation only; it is not strategy-performance evidence.
- **Validation:** Existing 12 paper/backtest tests pass; compileall, CLI help, and `git diff --check` pass. No exchange calls were used.
- **Limits:** The grid is intentionally small and coupled (stop width and RSI threshold move together); only spot settings are considered. News/sentiment remain contextual and are not converted into trade signals. The holdout has not been promoted as evidence of profitability. Live execution remains disabled while safe recovery and idempotency behavior for ambiguous order submission cannot be independently established.
