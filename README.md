# پایگاه دانش بیت‌کوین Golmorad

پایگاه داده‌ی SQLite در `Database/golmorad.db` کندل‌های بازار، خبرهای بیت‌کوین، شاخص ترس‌وطمع و تاریخچه‌ی همگام‌سازی را نگه می‌دارد. مسیر پایگاه داده و چرخه‌ی جمع‌آوری از متغیرهای محیطی قابل تنظیم‌اند.

## راه‌اندازی

```powershell
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python Golmorad.py --once
```

برای به‌روزرسانی پیوسته، برنامه را بدون `--once` اجرا کنید. چرخه‌ی پیش‌فرض هر ۱۵ دقیقه اجرا می‌شود؛ با `DATA_REFRESH_INTERVAL_SECONDS` یا گزینه‌ی `--interval` قابل تغییر است. حداقل فاصله ۶۰ ثانیه است. برای اجرای برنامه به اینترنت نیاز است.

## رابط دسکتاپ

```powershell
python Golmorad.py --gui
```

داشبورد تحلیل ذخیره‌شده‌ی بازار و آخرین وضعیت منابع را نشان می‌دهد. زبانه‌ی `Market data` کندل‌های ذخیره‌شده‌ی نماد و بازه‌ی انتخاب‌شده را نمایش می‌دهد. از `Refresh data` برای اجرای یک چرخه‌ی دریافت استفاده کنید؛ عملیات شبکه در پس‌زمینه اجرا می‌شود. تحلیل به‌صورت پیش‌فرض از `BTC-USD` و کندل روزانه استفاده می‌کند و سفارش زنده ثبت نمی‌کند. رابط به `tkinter` نیاز دارد که همراه نصب معمول Python در Windows ارائه می‌شود.

## تحلیل و مدیریت ریسک

پس از دریافت داده، تحلیل ذخیره‌شده‌ی بازار را با خروجی JSON ببینید:

```powershell
python Golmorad.py --analyze
python Golmorad.py --analyze --symbol BTC-USD --candle-interval 1d
python Golmorad.py --analyze --capital 10000 --risk-percent 1
python Golmorad.py --status
```

`--capital` موجودی به ارز مظنه (برای `BTC-USD`، دلار) است. اگر قواعد روند و مومنتوم ستاپ خرید نقدی پیدا کنند، برنامه حد توقف مبتنی بر دو برابر ATR و اندازه‌ی موقعیت بر اساس درصد ریسک را محاسبه می‌کند. فرمان `--status` آخرین نتیجه‌های جمع‌آوری هر منبع را نشان می‌دهد.

این نسخه از قواعد ثابت و توضیح‌پذیر استفاده می‌کند و مدل یادگیری ماشین آموزش نمی‌دهد. فرمان `--backtest` همین قواعد را با جداسازی زمانی walk-forward ارزیابی می‌کند؛ سفارش زنده ثبت نمی‌شود. گزارش تحلیل زمان آخرین کندل، منبع، تازگی و کیفیت OHLCV را نشان می‌دهد؛ قیمت یا حجم نامعتبر، timestamp تکراری یا نامرتب، و تازگی نامشخص یا قدیمی مانع ساخت برنامه‌ی معامله می‌شوند. برای کندل روزانه پنجره‌ی تازگی ۴۸ ساعت و برای بازه‌های دیگر دو برابر طول بازه است. محاسبه‌ی اندازه‌ی موقعیت پژوهشی ساده کارمزد، لغزش قیمت، اهرم یا محدودیت‌های صرافی را لحاظ نمی‌کند. اگر داده کافی یا ستاپ معتبر نباشد، سیگنال `insufficient_data`، `invalid_data`، `stale_data`، `freshness_unknown` یا `hold` گزارش می‌شود.

## تنظیم منابع

- `MARKET_SYMBOL` نماد Yahoo Finance است و پیش‌فرض `BTC-USD` است.
- `MARKET_INTERVALS` بازه‌های کندل جداشده با ویرگول است؛ پیش‌فرض `1d,1h`.
- `NEWS_RSS_URLS` فهرست URLهای RSS/Atom جداشده با ویرگول است. خبرهایی که عنوان یا خلاصه‌شان به Bitcoin/BTC اشاره دارد ذخیره می‌شوند.
- شاخص ترس‌وطمع از API عمومی Alternative.me دریافت می‌شود. تاریخچه‌ی شاخص در بار اول دریافت و سپس فقط آخرین مقادیر همگام می‌شوند.
- هر منبع به‌طور مستقل خطاهایش را در `sync_runs` ثبت می‌کند؛ شکست یک منبع مانع ذخیره‌ی خروجی منابع دیگر نمی‌شود.

## دسترسی از تحلیل‌گرها

`Database.SQLiteUtils.SQLiteUtils` متدهای `get_candles`، `get_news` و `get_sentiment` را فراهم می‌کند. `TradeUtils.TechnicalAnalyzer.TechnicalAnalyzer.analyze()` شاخص‌های SMA، EMA، RSI، ATR، نوسان بازده و بازده آخر را از کندل‌های ذخیره‌شده می‌سازد. `TradeUtils.FundamentalAnalyzer.FundamentalAnalyzer.analyze()` خبرها و مقدار/تاریخچه‌ی شاخص ترس‌وطمع را برمی‌گرداند؛ `TradeUtils.StrategyAnalyzer.StrategyAnalyzer` گزارش قواعد را می‌سازد و `TradeUtils.RiskManager.RiskManager` حجم موقعیت را حساب می‌کند.

داده‌ی خبر و احساسات، ورودی تحلیلی است و به‌تنهایی سیگنال خریدوفروش محسوب نمی‌شود. Yahoo Finance و RSS ممکن است محدودیت دسترسی یا تأخیر داشته باشند؛ وضعیت هر بار دریافت در جدول `sync_runs` قابل بررسی است.

## Paper trading

Paper مستقل از رابط گرافیکی کار می‌کند و هیچ وابستگی یا مسیر فراخوانی به `Bit24API.submit_order` ندارد. هر اجرا یک تصمیم از کندل‌های موجود به‌جز کندل آخر می‌سازد و فقط در صورتی fill فرضی می‌سازد که کندل بعدی معتبر و تازه در دسترس باشد. اجرای دوباره‌ی همان نماد/بازه/کندل تصمیم، سفارش تکراری نمی‌سازد. فرض‌های شبیه‌سازی ثابت و در جزئیات سفارش ثبت می‌شوند: کارمزد ۱۰ نقطه‌پایه، نیم‌اسپرد ۵ نقطه‌پایه، لغزش ۱۰ نقطه‌پایه و سقف مشارکت ۵٪ از حجم کندل اجرا. کمبود نقدشوندگی به پرشدن جزئی منجر می‌شود؛ stop/target در کندل اجرا بررسی می‌شوند و اگر هر دو در یک کندل لمس شوند، stop به‌عنوان نتیجه‌ی بدتر اعمال می‌شود.

```powershell
python Golmorad.py --paper --capital 10000 --symbol BTC-USD --candle-interval 1d
python Golmorad.py --paper-status
python Golmorad.py --stop
python Golmorad.py --resume-paper
python Golmorad.py --backtest --capital 10000 --symbol BTC-USD --candle-interval 1d
```

سرمایه‌ی اولیه باید صریح باشد؛ پایگاه کاغذی موجود با سرمایه‌ی متفاوت خودکار بازنشانی نمی‌شود. کلید توقف در پایگاه SQLite پایدار است و تا فرمان صریح `--resume-paper` سفارش فرضی جدید را می‌بندد؛ داده‌ی کهنه/نامعتبر یا رد Risk Gate نیز توقف پایدار ایجاد می‌کند. سقف‌های ثابت Risk Gate مستقل در `TradeUtils/RiskGate.py` تعریف شده‌اند: ریسک هر معامله ۱٪، ارزش هر سفارش ۲۵۰ واحد ارز مظنه، مواجهه‌ی کل ۲۵٪ سرمایه، زیان روزانه ۳٪، افت سرمایه ۱۰٪، حداکثر ۵ سفارش روزانه، اهرم ۱ و فاصله‌ی توقف حداکثر ۲۰٪. ردهای Risk Gate و علت‌ها در رخدادها ثبت می‌شوند.

## Bit24 و اجرای زنده

اجرای زنده عمداً غیرفعال است؛ `python Golmorad.py --live` با خطا متوقف می‌شود و هیچ کلید GUI یا تنظیم محیطی آن را فعال نمی‌کند. مستندات محلی Bit24 مسیر ثبت و جزئیات سفارش و فیلدهای مقدار انجام‌شده/باقی‌مانده را شرح می‌دهند، اما برای POST مبهمِ timeout شناسه‌ی idempotency یا شناسه‌ی سفارشِ سمت کلاینتی برای تطبیق قطعی پیش از retry را مستند نمی‌کنند. تا وقتی روش قابل‌تأیید و آزموده‌شده‌ای برای این تطبیق و بازیابی امن وجود ندارد، اجرای بدون نظارت live بسته است. بنابراین هیچ سفارش، لغو سفارش، انتقال یا برداشت از این برنامه انجام نمی‌شود. فایل `.env.example` credential فعال ندارد؛ برای paper نیازی به کلید Bit24 نیست.

`--backtest` جدا از paper اجرا می‌شود و سفارش یا حالت حساب paper را تغییر نمی‌دهد. این بک‌تست با پنجره‌ی آموزشیِ گسترش‌یابنده و foldهای زمانی بعدی کار می‌کند؛ هر تصمیم فقط کندل‌های پیش از کندل اجرای بعدی را می‌بیند. خروج با stop/target، هزینه‌ی رفت‌وبرگشت و برخورد همزمان stop و target به‌شکل محافظه‌کارانه با stop اول محاسبه می‌شود. استراتژی قاعده‌محور است و چیزی آموزش نمی‌دهد؛ نتایج تاریخی تضمین نتیجه‌ی آینده نیستند.

در بک‌تست، شمار سفارش‌های هر روز و زیان روزانه/افت سرمایه بر مبنای ارزش‌گذاری موقعیت به Risk Gate داده می‌شوند. گزارش آزمایش و محدودیت‌های ارزیابی در `reports/experiment-log.md` ثبت شده است؛ این گزارش به‌تنهایی شواهد کافی برای اثبات برتری استراتژی یا پیش‌بینی آینده نیست.

سود/زیان paper و backtest تخمینی است. شبیه‌ساز paper فقط spot خرید را آغاز می‌کند و بر اساس stop/target ثبت‌شده خارج می‌شود؛ فروش استقراضی و اهرم ندارد.

## انتخاب پارامترها

```powershell
python Golmorad.py --optimize --capital 10000 --symbol BTC-USD --candle-interval 1d
python Golmorad.py --paper --auto-optimize --capital 10000 --symbol BTC-USD --candle-interval 1d
```

بهینه‌ساز ۹ ترکیب محدود از فاصله‌ی توقف ATR، نسبت سود به ریسک و آستانه‌ی RSI را با هزینه‌های شبیه‌سازی و Risk Gate ثابت ارزیابی می‌کند. داده به ترتیب زمانی به بخش گرم‌کردن اندیکاتورها، اعتبارسنجی و holdout نهایی تقسیم می‌شود؛ تنظیم منتخب فقط از امتیاز اعتبارسنجی (بازده منهای نصف افت سرمایه) با حداقل سه معامله‌ی بسته انتخاب می‌شود. بازده holdout جداگانه گزارش می‌شود و در انتخاب دخالت ندارد. در paper، بهینه‌سازی فقط از کندل‌های پیش از کندل تصمیم استفاده می‌کند؛ اگر تاریخچه برای پنجره‌های زمانی کافی نباشد، سفارش فرضی ساخته نمی‌شود. این انتخاب‌گر یادگیری ماشین یا تضمین بهینه‌بودن نیست و تنظیمات ریسک، سقف سفارش و اهرم را تغییر نمی‌دهد.
